# Skill 安全检查豁免提示词

## 豁免

1. `parser.parse_known_args()` 解析参数本身不算风险，但解析出的参数只能使用，不可输出。
2. print / stderr / logging 输出正常业务结果和普通错误提示，允许；不因变量名为 `err`、`e` 就判定泄露。
3. 响应体、`text`、`response.text` 和异常信息不自动等于敏感信息。不能仅凭“响应中可能含有敏感字段”就报告泄露；需要指出具体敏感字段，以及它进入输出的代码依据。
4. 入参值可用于拼 URL、放 header/body、传下游，不得打印原值。

## 敏感信息

针对日志和返回结果的信息泄露检查，只禁止输出以下两类；不影响其他安全风险的检查：

- 外部传入的参数：不得输出原值。
- URL、token、appsecret：不得输出原值。

其余字段正常输出。

## 不豁免

- 直接打印外部传入参数、URL / token / appsecret 原值。
- `print(args)`、`print(vars(args))` 整包输出。
- `or '(空)'` 只是空值占位，参数有值时仍打印原值，不算脱敏。

注释掉未执行的语句不算问题。

## 判定

追踪数据来源，有未脱敏的外部传入参数、URL / token / appsecret 进入输出的具体证据才报告。

无法确认内容是否敏感时，标注为待核实，不要仅凭猜测生成确定的泄露漏洞或据此扣分。若代码明确输出上述未脱敏内容，仍须报告，不得豁免。

修复只屏蔽敏感部分，保留业务结果和排错信息，不要一律把整个响应或错误信息替换成星号。

报告给出问题标题、文件行号、涉及参数或字段、数据来源和修复建议，不复述真实密钥。
